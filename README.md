# 🎓 Розробка автономної роботизованої системи для детекції та знищення бур'янів

## 📑 Анотація

У даній роботі розроблено програмно-апаратний комплекс для автономної навігації та селективного знищення бур'янів у сільському господарстві. Система базується на використанні згорткових нейронних мереж (CNN) архітектури **YOLOv8** для детекції об'єктів у реальному часі та одноплатного комп'ютера **Raspberry Pi 4** для обробки даних.

**Ключові слова:** *Computer Vision, YOLOv8, Robotics, IoT, Raspberry Pi, Precision Agriculture, Autonomous Navigation.*

---

## 1. 🛠️ Апаратне забезпечення (Hardware)

Система побудована на базі доступних компонентів, що забезпечують баланс між продуктивністю та енергоефективністю.

### 1.1. Обчислювальний модуль
*   **Raspberry Pi 4 Model B (4GB RAM):** Головний бортовий комп'ютер. Виконує задачі комп'ютерного зору, планування маршруту та веб-серверу.
    *   *ОС:* Raspberry Pi OS (64-bit).
    *   *Роль:* "Мозок" системи.
*   **ESP32 DevKit V1:** Мікроконтролер для низькорівневого керування периферією.
    *   *Зв'язок:* UART (Serial) через USB.
    *   *Роль:* Генерація ШІМ (PWM), обробка переривань.

### 1.2. Сенсори та Зір
*   **Камера:** Raspberry Pi Camera Module v2 (або аналог з підтримкою libcamera).
    *   *Інтерфейс:* CSI (Camera Serial Interface) — забезпечує мінімальну затримку передачі кадрів.
    *   *Роздільна здатність:* 320x240 (для інференсу), 640x480 (для стрімінгу).

### 1.3. Виконавчі механізми (Actuators)
*   **Двигуни постійного струму (DC Motors):** 2 шт. з редуктором (жовті TT-мотори або N20).
*   **Драйвер двигунів:** L298N або TB6612FNG. Забезпечує керування напрямком та швидкістю обертання коліс.
*   **Сервопривід (Servo):** MG996R або SG90. Використовується як маніпулятор для фізичного знищення бур'яну (механічний вплив або точкове обприскування).

### 1.4. Живлення
*   **Акумулятор:** Li-Ion збірка 2S (7.4V) або 3S (11.1V).
*   **DC-DC Перетворювачі:** LM2596 (Step-Down) для стабілізації 5V/3A для живлення Raspberry Pi.

## 2. 🏗️ Архітектура та Взаємодія Компонентів

Система реалізована як розподілена мережа компонентів, що взаємодіють у реальному часі.

### 2.1. Схема потоків даних (Data Flow Pipeline)

1.  **Захоплення (Acquisition):** Камера передає RAW-дані через CSI інтерфейс у пам'ять Raspberry Pi.
2.  **Обробка (Processing):**
    *   Зображення конвертується у формат, придатний для нейромережі ($320 \times 320 \times 3$, float32).
    *   **ONNX Runtime** виконує пряме поширення (inference) моделі YOLOv8n.
3.  **Логіка (Decision Making):**
    *   Отримані Bounding Boxes фільтруються за порогом впевненості (Confidence Threshold > 0.5).
    *   Визначаються координати центроїдів об'єктів $(x_c, y_c)$.
    *   Розраховується відхилення від центру кадру для корекції курсу.
4.  **Керування (Control):**
    *   Команди руху (швидкість ліва/права) формуються у JSON-пакет.
    *   Пакет надсилається через Serial порт на ESP32.
5.  **Виконання (Execution):**
    *   ESP32 парсить пакет і встановлює відповідні Duty Cycle для ШІМ-сигналів драйвера двигунів.

### 2.2. Протокол взаємодії (Raspberry Pi <-> ESP32)

Обмін даними відбувається через UART на швидкості **115200 baud**.
Формат пакету (JSON):
```json
{
  "L": 150,   // Швидкість лівого двигуна (-255...255)
  "R": 150,   // Швидкість правого двигуна (-255...255)
  "S": 0      // Стан сервоприводу (кут 0-180)
}
```

## 3. 🔬 Математичне забезпечення

### 3.1. Математична модель детекції (YOLOv8)
Архітектура YOLOv8 використовує **Anchor-Free** підхід, що спрощує детекцію об'єктів різного масштабу.

Функція втрат (Loss Function):
$$ \mathcal{L}_{total} = \lambda_{box} \mathcal{L}_{box} + \lambda_{cls} \mathcal{L}_{cls} + \lambda_{dfl} \mathcal{L}_{dfl} $$

Де:
- $\mathcal{L}_{box}$ (Box Loss) — CIoU Loss, враховує перекриття, відстань між центрами та співвідношення сторін.
- $\mathcal{L}_{cls}$ (Class Loss) — Binary Cross Entropy для класифікації (Бур'ян vs Культура).

### 3.2. Проективне перетворення (Pixel to Metric)
Для визначення реального положення бур'яну відносно робота використовується спрощена модель камери-обскури (Pinhole Camera Model).
Якщо камера встановлена під кутом $\alpha$ на висоті $h$:

$$ Y_{real} = h \cdot \tan(\alpha + \arctan(\frac{v - c_y}{f_y})) $$
$$ X_{real} = Y_{real} \cdot \frac{u - c_x}{f_x} $$

Де $(u, v)$ — піксельні координати, $(c_x, c_y)$ — оптичний центр, $(f_x, f_y)$ — фокусна відстань.

### 3.3. Кінематична модель робота (Virtual Odometry)
Для розрахунку позиції робота на карті використовується інтегрування швидкостей (Dead Reckoning):

$$
\begin{cases}
x_{t+1} = x_t + v \cdot \cos(\theta_t) \cdot \Delta t \\
y_{t+1} = y_t + v \cdot \sin(\theta_t) \cdot \Delta t \\
\theta_{t+1} = \theta_t + \omega \cdot \Delta t
\end{cases}
$$

Де $v = \frac{v_R + v_L}{2}$ — лінійна швидкість, $\omega = \frac{v_R - v_L}{L}$ — кутова швидкість ($L$ — база робота).

## 4. 💻 Програмна реалізація

### 4.1. Технологічний стек
*   **Python 3.13:** Основна мова розробки.
*   **OpenCV (cv2):** Обробка зображень, малювання графіки.
*   **Ultralytics YOLO:** Фреймворк для тренування та експорту моделей.
*   **ONNX Runtime:** Рушій для прискореного запуску нейромереж на CPU.
*   **Flask + SocketIO:** Асинхронний веб-сервер для стрімінгу відео та телеметрії.

### 4.2. Структура проекту
```text
weed-system/
├── app.py                  # Головний файл. Ініціалізує камеру, модель та веб-сервер.
├── robot_controller.py     # Клас RobotController. Відповідає за Serial-порт та одометрію.
├── config/                 # Налаштування системи.
│   ├── config.yaml         # Параметри камери, пороги детекції, PID-коефіцієнти.
│   └── plant_classes.yaml  # Список класів рослин (ID -> Назва).
├── web/                    # Frontend частина.
│   ├── templates/index.html # SPA (Single Page Application) інтерфейс.
│   └── static/             # JS скрипти для малювання карти та графіків.
└── esp32/                  # Прошивка мікроконтролера.
```

- Python 3.9+
- Встановлені драйвери камери (libcamera)

